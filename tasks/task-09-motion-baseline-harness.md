# Task 09: Motion-Baseline Artifact Harness

## Objective
Establish the `tests/playwright/motion-baselines/` directory structure, manifest schema, and any shared Playwright helpers for keyframe capture and comparison. This harness is the infrastructure that scenario specs (tasks 10–12) use to commit and compare keyframe PNGs.

## Context

**Quick Context:**
- The mugshot suite stores committed PNG baselines in `tests/playwright/mugshot-baselines/<Char>/ideal/` and compares them via Playwright's `toHaveScreenshot()` or a custom pixel-diff helper.
- Task-02 (video spike) may have already created stub `manifest.json` files under `motion-baselines/`. If so, flesh them out here.
- The motion-baseline harness is analogous to mugshot but for motion keyframes: 2–3 committed PNGs per scenario at specific moments (on platform, falling, respawned; approaching, blocked; base, mid-climb, top).
- TDD does not apply to scaffolding and harness tasks.

### 2. Manifest schema
Each `manifest.json` follows this shape:
```json
{
  "scenario": "corridor",
  "description": "Walk-off-and-respawn: character walks along corridor, falls off far end, respawns.",
  "geometry": "scenario-corridor map — 2x1x8 colored_block_blue platform",
  "spawnPoint": { "x": 0, "y": 2, "z": 0 },
  "keyframes": [
    {
      "id": "keyframe-01-on-platform",
      "filename": "ideal/keyframe-01-on-platform.png",
      "captureCondition": "bot.pos.z >= 4 and bot.pos.y within 0.3 of platform top",
      "description": "Bot walking on platform, roughly at midpoint"
    },
    {
      "id": "keyframe-02-falling",
      "filename": "ideal/keyframe-02-falling.png",
      "captureCondition": "bot.vel.y <= -4 m/s (clearly falling)",
      "description": "Bot in free-fall past platform edge"
    },
    {
      "id": "keyframe-03-respawned",
      "filename": "ideal/keyframe-03-respawned.png",
      "captureCondition": "bot.pos within 1m of spawn point and bot.pos.y within 0.3 of platform top",
      "description": "Bot settled back at spawn point"
    }
  ],
  "assertionThresholds": {
    "positionTolerance": 0.3,
    "velocityTolerance": 0.1,
    "keyframePixelDiffPercent": 0.02
  }
}
```

Populate `scenario-corridor/manifest.json`, `scenario-collision/manifest.json`, and `scenario-stairs/manifest.json` with appropriate values for each scenario (see updated-prd.md for keyframe conditions).

### 3. Shared helpers: `tests/playwright/motion-helpers.ts`
Add a helper file with utilities the scenario specs share:

```ts
import { Page, expect } from '@playwright/test';

/** Wait until a bot (by playerId in the store) reaches a condition. */
export async function waitForBotCondition(
  page: Page,
  botId: string,
  predicate: (pos: {x:number;y:number;z:number}, vel: {x:number;y:number;z:number}) => boolean,
  timeoutMs = 15_000,
  pollingMs = 100,
): Promise<void>;

/** Capture a canvas keyframe screenshot to a named file for baseline comparison.
 * Uses Playwright's toHaveScreenshot for committed baselines, or page.screenshot
 * for non-committed human-review captures. */
export async function captureMotionKeyframe(
  page: Page,
  snapshotName: string,
  options?: { committed?: boolean; outputDir?: string }
): Promise<void>;

/** Read a motion manifest from motion-baselines/<scenario>/manifest.json */
export function readMotionManifest(scenario: string): MotionManifest;
```

Implement `waitForBotCondition` using the `__OFFICE_STORE__` window hook pattern from `debug-character-grounded.spec.ts`. Implement `captureMotionKeyframe` using Playwright's `page.screenshot()` plus `expect(page).toHaveScreenshot(snapshotName)` for committed baselines.

### 4. README.md
Create `tests/playwright/motion-baselines/README.md`:
```markdown
# Motion Baseline Artifacts

Keyframe PNG baselines for motion regression scenarios. Analogous to
mugshot-baselines/ but for motion (walking, falling, collision, stairs).

## Structure
Each scenario has:
- `ideal/` — committed PNG keyframes. Generated by running the spec once
  and approving the output. Re-commit when the scenario geometry or
  character physics intentionally changes.
- `manifest.json` — scenario description, capture conditions, thresholds.

## Updating baselines
Run the spec with `--update-snapshots`:
  pnpm exec playwright test tests/playwright/scenario-<name>.spec.ts --update-snapshots

Review each updated PNG before committing. Do NOT widen pixel-diff
thresholds to make a suite green — investigate the physics regression.

## When to re-bake
If the scenario geometry changes (layout edited, bake re-run), the ideal/
keyframes need refreshing because the camera framing and character position
will differ. Re-run the spec in generate mode, review, commit.
```

## Implementation Details
- The `ideal/` directories are initially empty — scenario specs (tasks 10–12) will generate and commit the first keyframes.
- `waitForBotCondition` is the motion-suite analog of `waitForCanvasReady` — it polls the store.
- `captureMotionKeyframe` for committed baselines: use `expect(page).toHaveScreenshot(snapshotName, { maxDiffPixelRatio: 0.02 })` where `maxDiffPixelRatio` comes from the manifest's `assertionThresholds.keyframePixelDiffPercent`.
- TDD does not apply to this harness. The helpers are utility code for the specs.
