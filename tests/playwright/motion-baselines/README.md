# Motion Baseline Artifacts

Keyframe PNG baselines for motion regression scenarios. Analogous to
`mugshot-baselines/` but for motion (walking, falling, collision, stairs).

## Structure

Each scenario has:
- `ideal/` — committed PNG keyframes. Generated by running the spec once
  and approving the output. Re-commit when the scenario geometry or
  character physics intentionally changes.
- `manifest.json` — scenario description, capture conditions, assertion
  thresholds, and spawn coordinates.

```
motion-baselines/
  scenario-corridor/
    ideal/keyframe-01-on-platform.png     (populated by task-10 spec)
    ideal/keyframe-02-falling.png
    ideal/keyframe-03-respawned.png
    manifest.json
  scenario-collision/
    ideal/keyframe-01-approaching.png     (populated by task-11 spec)
    ideal/keyframe-02-blocked.png
    manifest.json
  scenario-stairs/
    ideal/keyframe-01-base.png            (populated by task-12 spec)
    ideal/keyframe-02-mid-climb.png
    ideal/keyframe-03-top.png
    manifest.json
  VIDEO-COMPARISON-SPIKE.md              (task-02 investigation findings)
```

## Updating baselines

Run the spec with `--update-snapshots`:

```bash
pnpm exec playwright test tests/playwright/scenario-corridor.spec.ts --update-snapshots
pnpm exec playwright test tests/playwright/scenario-collision.spec.ts --update-snapshots
pnpm exec playwright test tests/playwright/scenario-stairs.spec.ts --update-snapshots
```

Review each updated PNG before committing. Do NOT widen pixel-diff
thresholds to make a suite green — investigate the physics regression.

## When to re-bake

If the scenario geometry changes (layout edited, bake re-run), the `ideal/`
keyframes need refreshing because the camera framing and character position
will differ. Re-run the spec in generate mode, review, commit.

## Regression gate

The committed regression gate for every motion scenario spec is:

1. **Numeric assertions** on `pos` and `vel` vectors from `__OFFICE_STORE__`
   at scenario key moments — using the `waitForBotCondition` helper in
   `tests/playwright/motion-helpers.ts`.
2. **Keyframe PNGs** captured via `captureMotionKeyframe` at those same
   moments, compared against committed ideals in `ideal/` via Playwright's
   `toHaveScreenshot()` with `maxDiffPixelRatio` from the manifest's
   `assertionThresholds.keyframePixelDiffPercent`.

Video comparison (`lib/video-compare.ts`) is a **failure-investigation aid**
only — see `VIDEO-COMPARISON-SPIKE.md` for the rationale.

## Adding a new scenario

1. Create `motion-baselines/<scenario-name>/` with `manifest.json` and an
   empty `ideal/` directory (with `.gitkeep`).
2. Write a `tests/playwright/scenario-<name>.spec.ts` that uses
   `waitForBotCondition` and `captureMotionKeyframe` from `motion-helpers.ts`.
3. Run the spec once with `--update-snapshots` to generate the initial PNGs.
4. Inspect the PNGs manually, then commit both the spec and the `ideal/` PNGs.
